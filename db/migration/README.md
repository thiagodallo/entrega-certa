# db/migration: a criação das tabelas

Cada arquivo daqui cria ou altera tabelas. O Alembic, que faz o papel do Flyway, executa os arquivos em ordem quando a API sobe.

**Nesta etapa:** crie as migrations de todas as tabelas do modelo, uma tabela por arquivo.

- O nome é `V<número>__<o_que_faz>.py`, com **dois** sublinhados. Exemplo: `V1__criar_turmas.py`.
- A ordem é a do `down_revision`: cada arquivo aponta para o anterior. O primeiro usa `None`.
- Tabela no plural e em `snake_case` (`turmas`, `data_entrega`); chave estrangeira com `REFERENCES`.
- **Nunca edite uma migration que já rodou.** Para corrigir, crie a próxima (`V2__...`). Se o banco ainda está só na sua máquina, recrie do zero com `docker compose down -v`.

Para criar o arquivo já com o nome e os campos certos:

```bash
uv run python -m alembic revision --rev-id V1 -m "criar turmas"
```

O SQL vai dentro do `op.execute`:

```python
from alembic import op

revision = "V1"
down_revision = None


def upgrade() -> None:
    op.execute(
        """
        CREATE TABLE turmas (
            id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
            nome VARCHAR(255) NOT NULL
        )
        """
    )
```
